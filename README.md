# zcode-plugins-libre

A libre plugin marketplace for [ZCode](https://github.com/anomalyco/ZCode):
permissively-licensed, provenance-tracked re-hosts of open-source agent skills
and CLI skill wrappers — no paid-plan gating, no proprietary services.

Marketplace ID: **`zcode-plugins-libre`**

```
marketplace.json   # catalog (generated by build.mjs — do not hand-edit hashes/URLs)
build.mjs          # deterministic packaging: plugins/* -> dist/*.zip + catalog
plugins/<name>/    # one source tree per plugin (.zcode-plugin/plugin.json at its root)
icons/<name>.png   # marketplace-level icons (absolute raw.githubusercontent URLs)
dist/              # built zips — attach these to the GitHub release (not committed)
```

## License policy

- Only permissively-licensed content is accepted: MIT, Apache-2.0, BSD, and
  equivalents. No proprietary, copyleft-incompatible-for-redistribution, or
  paid-plan-gated plugins. Catalog entries never set `requiresPaidPlan`.
- Every plugin carries the full canonical license text (`LICENSE` /
  `LICENSE.txt`) with honest copyright attribution, plus a `UPSTREAM.md`
  recording the origin repository, the exact upstream commit/tag adapted from,
  the artifact the re-host was based on, and an itemized list of local changes.
- Upstream license notices are kept verbatim — including third-party copyright
  sections that still apply (e.g. the obsidian aggregate `LICENSE`).
- Icons are brand marks of the respective upstream projects, used referentially
  to identify them in the plugin store.

## How the mirror works

- **Catalog**: register this marketplace in ZCode pointing at
  `https://raw.githubusercontent.com/yeyuan98/zcode-plugins/main/marketplace.json`.
  A jsDelivr mirror of the catalog is also possible:
  `https://cdn.jsdelivr.net/gh/yeyuan98/zcode-plugins@main/marketplace.json`
  (jsDelivr caches aggressively; the raw URL is the source of truth and updates
  fastest).
- **Plugin zips**: `source.url` in each entry points at a GitHub Release asset
  (`https://github.com/yeyuan98/zcode-plugins/releases/download/v1.0.0/<name>-<version>.zip`).
  Note jsDelivr does not proxy GitHub Release assets, so zips always download
  from github.com directly. Each entry pins the zip's `sha256`.
- **Icons**: served from `raw.githubusercontent.com` (absolute https URLs, as
  the marketplace schema requires).

## Adding a plugin

1. Create `plugins/<name>/` containing the plugin tree with
   `.zcode-plugin/plugin.json` at its root (this is what the zip must contain
   under a single top-level `<name>/` directory). Include `README.md`, the full
   canonical `LICENSE`, and a `UPSTREAM.md` (origin repo, commit/tag, license,
   local changes). Optionally a `.claude-plugin/plugin.json` compatibility
   mirror.
2. Drop an icon at `icons/<name>.png` if one should be shown (omit for the
   letter-avatar fallback).
3. Add a catalog stanza (display name, category, license, upstream
   homepage/repository, keywords) for the plugin in `build.mjs`.
4. Run `node build.mjs` — it builds `dist/<name>-<version>.zip`
   deterministically and regenerates `marketplace.json` with release URLs and
   sha256 hashes. Two runs on the same tree produce byte-identical zips.
5. Bump `RELEASE_TAG` in `build.mjs` if this is a new release, re-run, then
   commit `plugins/`, `icons/`, `marketplace.json`, `build.mjs` and attach
   `dist/*.zip` to the matching GitHub release.

## Verification

After any change, `node build.mjs` plus a quick check that each
`dist/<name>-<version>.zip` contains exactly one root directory `<name>/` with
`.zcode-plugin/plugin.json` inside (the layout the ZCode installer expects)
and that `marketplace.json`'s `sha256`/`url` fields match the built zips.
